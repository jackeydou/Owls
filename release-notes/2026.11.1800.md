## Before You Install

- This is Owlto's first stable release. It covers everything since Owls 2026.9.801, including every beta in between.
- Owls 2026.9.801 and earlier do not update to Owlto. Owlto installs as a new app with its own data, so threads, projects, and settings from Owls are not carried over.
- Owlto needs macOS 13 or later.
- Beta installs that follow the stable channel (the default since 2026.11.1700-beta.3) update to this release.

## Features

- Owlto is a Router you talk to. It sends work to the Claude Code, Codex, or Cursor CLI on your computer as workers, and each worker that changes code gets its own git worktree and branch, so several can work at once.
- Threads are global: start one with Command-N, send work to any project with @, and forward messages or worker results to other threads. Archive threads you are done with.
- Worker panels read as one conversation that leads with the report, show a +N/-N change summary with per-file diffs, the branch's pull request and CI checks, and an Open in menu for your editor, Finder, or terminal. You can message a busy worker, queue messages, or steer it.
- Workers report back through a dedicated report tool, and their reports reach the Router in full.
- Workers can browse the web: Claude Code workers use Claude in Chrome, and Codex and Cursor workers get a Playwright browser tool. Each worker runs at the permission level you set in Settings.
- Fewer approval cards: in Workspace access, Claude Code and Codex approve safe actions for you. A notification and dock badge tell you when a worker needs your approval or answer.
- Memory keeps your preferences and project knowledge from past threads and uses them in new ones. Review, edit, pin, and export memories in Settings.
- Notes: save Router replies, worker results, or selected text as notes, organize them by tag and on boards, and attach them to messages. Notes are plain Markdown files you can edit in any app, and the Router and workers can save and read them.
- Automations: schedule tasks from the Automation page, and send pull request follow-ups back to the worker that opened the PR.
- A Pull Requests page lists every pull request agents opened, with merge, review, and CI status.
- Projects: open a folder, clone a GitHub repository (private ones too), or Quick start an empty project. Each project has its own settings, icon, and ordered list of agents and models. Tasks without a project run in the Workspace, which shows as the first project.
- Click a file path in an agent message to open it in a File viewer inside Owlto. Mermaid diagrams render in messages and notes.
- A Usage entry shows how much of each agent's plan is left, and Settings → Usage stats shows tokens, cache hit rate, and estimated cost per day.
- A first-run welcome walks you through connecting the coding agents you choose and picking who runs the Router.
- Owlto updates itself in the background and installs on restart, and most updates download only what changed.
- Personalize Owlto with a Profile page, nine doodle owl app logos, and the Doodle style from the Owlto website.
- Send feedback as a GitHub issue from the title bar.

## Bug Fixes

- Agents opened from Finder now find CLIs installed with Homebrew or a version manager, such as gh and node.
- Claude Code workers no longer end a turn with an empty report after resuming with a leftover background task.
- Picking a Cursor model in project settings no longer fails with "This request is invalid".
- Tasks outside any project start in the Workspace instead of failing.
- Long Router conversations keep using the model provider's prompt cache.
- Menus, the update popup, and message actions respond to clicks reliably, and focus no longer draws a thick black outline.
