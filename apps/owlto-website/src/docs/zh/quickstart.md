这份教程大约需要十分钟，再加上智能体干活的时间。读完后，你会向协调者（Router）提出一个改动，看着两个 Worker 在各自的分支上完成它，并把结果合并进来。

## 开始之前

- 已安装 Owlto。见[安装 Owlto](/docs/install/)。
- 至少连接了一个智能体，并设置好了协调者。见[连接编程智能体](/docs/connect-agents/)。
- 你有一个至少提交过一次的 git 仓库，而且想让 Worker 看到的内容都已经提交。Worker 只从已提交的文件开始工作。

第一次试用，选一个小而低风险的改动，放在一个出错也无所谓的仓库里。

## 第 1 步：添加项目

点击**项目**侧栏里的添加按钮，选择其中一种：

- **打开项目**：本机已有的文件夹（也可以按 `⌘O`）。
- **打开 GitHub 项目**：把仓库克隆到 `~/Owlto/projects`。私有仓库可能需要先在**设置 → GitHub** 中连接 GitHub。
- **快速创建**：新建一个空项目，并初始化为 git 仓库，方便 Worker 使用 worktree。

项目会出现在侧栏和全景地图上。

## 第 2 步：向协调者提需求

1. 按 `⌘N` 新建对话。
2. 输入 `@` 并选择你的项目。在新对话里，第一个提到的项目会成为这段对话的默认项目。
3. 描述要做的事。两个互不相关的改动最能体现并行，例如：

```text
在这个项目里做两件小事：
1. 在 README.md 里加一个“开发”小节，说明如何安装依赖和运行测试。
2. 找到测试配置，加一个以监听模式运行测试的脚本。
每个任务用一个 Worker。
```

4. 按 `⌘↵` 发送。在对话输入框里，`Enter` 是换行。

## 第 3 步：看 Worker 开工

协调者会回复它启动了哪些任务，然后结束这一轮。每个 Worker 会以卡片形式出现在对话里和全景地图上（`⌘J`）。Worker 在后台运行，完成后协调者会主动汇报，你不必一直盯着这段对话。

每个改代码的 Worker 都有自己的 git worktree，分支名是 `owlto/w_` 加 8 个字符，例如 `owlto/w_1a2b3c4d`。你自己的工作副本不会被改动。

## 第 4 步：处理批准请求

当 Worker 想做超出其权限的事，例如在任务文件夹之外运行命令，请求会停在输入框上方：“*智能体* 需要你处理”。Worker 卡片和 Worker 自己的对话里也会显示。

- **仅本次允许**：只允许这一次。
- **拒绝**：不允许。Worker 会在没有这一步的情况下继续，或者汇报它被卡住了。

没有“始终允许”按钮。想少被打扰，可以在**设置 → 协调者与 Worker → Worker** 中提高该智能体的权限。见[与 Worker 沟通并处理批准](/docs/steer-workers/)。

## 第 5 步：查看某个 Worker

点击 Worker 卡片打开它的面板，可以看到它的对话：读了什么、运行了什么、改了什么。在面板的输入框里输入内容，就能直接和这个 Worker 对话。如果它正在忙，消息会排队，等这一轮结束再发送；也可以把消息插入正在进行的这一轮。

## 第 6 步：审阅改动

Worker 改过文件后，面板标题处会显示新增和删除的行数。点击它可以查看文件改动：每个改动的文件及其 diff。再点一次回到对话。

想仔细看，可以用**打开方式**在你的编辑器或终端里打开这个 Worker 的文件夹。对于使用 worktree 的 Worker，打开的是 worktree，而不是你的工作副本。

## 第 7 步：合并结果

Worker 完成后，协调者会汇总改了什么，并给出每个分支名。Owlto 不会替你合并。你可以任选一种方式：

- **在本地合并。**在你自己的工作副本里运行：

```bash
git merge owlto/w_1a2b3c4d
```

- **创建 Pull Request。**告诉协调者，例如“把 README 那个分支推上去并创建 PR”。Worker 会用你本机的 git 凭据推送，并用它的智能体可用的工具（例如 `gh` CLI）创建 PR。连接 GitHub 后，这个 PR 会出现在 **Pull requests** 页面。
- **让协调者合并到你的工作副本。**协调者可以派一个 Worker 直接在你的工作副本里合并某个分支。请先提交你自己的改动。

如果两个分支改了同一处代码，合并第二个时 git 会报冲突。像处理普通合并冲突一样解决它，或者让协调者派一个 Worker 来解决。见[审阅并合并 Worker 的结果](/docs/review-and-merge/)。

## 第 8 步：清理

打开已完成的 Worker，选择**移除 Worker**，或者删除整段对话。Owlto 会删除没有未提交改动的 worktree，并删除提交已经进入你工作副本的分支。有未合并提交的分支会保留；有未提交改动的 worktree 也会保留，并列在**保留的 worktree** 中，点击**丢弃**可以彻底删除。
