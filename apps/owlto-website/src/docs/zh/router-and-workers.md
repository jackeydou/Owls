Owlto 有两种角色。**协调者**（英文界面为 Router）是和你对话的那一个，**Worker** 负责干活。把两者分开，你就能在多个智能体改代码的同时，只读一段对话。

## 协调者

协调者把你的需求拆成任务，把每个任务交给一个 Worker，跟踪它们，并汇总结果。它可以：

- 派发任务给 Worker，并选择项目、智能体、模型、权限和起始分支
- 列出对话中的 Worker，给某个 Worker 发消息，或停止某个 Worker
- 开启记忆功能时，跨对话记住信息并搜索这些记忆
- 创建和管理自动化任务

协调者从不亲自干活。无论用哪种引擎运行，它都没有修改文件或运行命令的工具，也不能替你批准请求。

协调者可以运行在 Claude Code、Codex 或 Owlto 内置引擎中；内置引擎使用你提供的模型 API key 或本地端点。Cursor 不能运行协调者。在**设置 → 协调者与 Worker → 协调者**中选择。见[连接编程智能体](/docs/connect-agents/#选择由谁运行协调者)。

Worker 在后台运行。派发之后，协调者会告诉你启动了什么，然后结束这一轮。某个 Worker 完成后，协调者阅读它的汇报，再决定派发下一步还是向你汇报。

## Worker

一个 Worker 就是在你 Mac 上某个编程智能体（Claude Code、Codex 或 Cursor）里运行的一个任务。每个 Worker 都有：

- 自己的对话，你可以打开并回复
- 一个文件夹：自己的 git worktree（位于 `owlto/w_…` 分支），或者项目文件夹本身（见[项目、Workspace 与 worktree](/docs/projects-and-worktrees/)）
- 一种权限：只读、工作区访问或完全访问
- 完成时写的汇报，包括它提交到的分支

同一段对话里的 Worker 可以在不同项目中工作。后续 Worker 可以从前一个 Worker 的分支开始。

## 如何为 Worker 选择智能体和模型

对每个任务，Owlto 依次确定：

1. **智能体**：协调者指定的智能体。没有指定时，用项目里第一个勾选且已连接的智能体；项目没有勾选任何智能体时，任何已连接的智能体都可以。
2. **模型**：协调者指定的模型。否则用项目为该智能体设置的第一个模型，或**设置 → 协调者与 Worker → Worker** 中该智能体的默认模型。
3. **权限**：协调者指定的权限，但不超过 **Worker 最高权限**。否则用该智能体的默认权限。

只有当你要求、或任务明显更适合项目中的其他选项时，协调者才会指定智能体或模型。想影响它的选择，可以直接在需求里说明（“测试交给 Claude Code”），或者设置项目的**编码 Agent**。

## 角色对比

| | 协调者 | Worker |
| --- | --- | --- |
| 你和谁对话 | 一直是它 | 打开它或用 `@` 提到它时 |
| 修改文件、运行命令 | 从不 | 可以，在权限范围内 |
| 运行在 | Claude Code、Codex 或 Owlto（内置） | Claude Code、Codex 或 Cursor |
| 批准 | 不能替你批准任何操作 | 操作超出权限时会请你批准 |
| 产出 | 计划和汇总 | 分支上的提交，以及一份汇报 |
